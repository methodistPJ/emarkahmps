# Known limitations and live acceptance gate

- No production Google project/database/URL/trigger/deployment was accessed or modified. All new integration tests are local browser plus actual application backend with synthetic Google-service doubles. Operator staging tests are required before production use.
- Actual Microsoft Excel Windows/Mac editing, native dropdown behaviour/protection and actual Safari/iPad/iPhone were not run. XLSX XML/types/validations/protection were inspected read-only, all10 sheet views rendered, and the real shipped file parsed/imported in Chromium. The artifact renderer displays some numeric-looking text/bools differently from the native stored types; raw XLSX and browser parsing independently confirm025849 is text and retains its zero. Native Excel acceptance remains mandatory.
- Supported .xlsx only; no .xls/.xlsm, encryption, ZIP64, date1904, formula/error input, external links/hyperlinks or embedded objects. Limits apply per workbook, not a measured cloud throughput guarantee. Headers/reference protected without password are an editing aid, not security.
- Preview expires15 minutes. Full detail is fetched through a separate authorized read to avoid a45000-character WAL response cell. Heavy credential preparation may require fresh validation if the operator waits too long. Browser workbook/credential memory is not persisted for recovery; after refresh, re-upload/validate. Server receipts and deterministic matching handle committed imports.
- Existing enrolment transfers/status changes, class-teacher replacement, account/class deactivation and prepared exam config/cohort additions are rejected for manual review. Missing rows do not delete. Subject co-teachers are additive. Inactive old refs/assignments need reviewed admin resolution; import is not a historical reconciliation tool.
- New exams stay DRAFT even when workbook intent is OPEN; an administrator must check readiness/dates and explicitly prepare/open. Pending activation is a warning, not an exemption from session blocking. Existing new-year/archive/PDF workflows retain their documented boundaries.
- The common temporary PIN requires a private per-user code. Code/ticket expiry and rate limits do not compensate for poor private distribution or compromised administrator browser. Issuance responses are intentionally not replayable with raw secrets; reissue if lost.
- Permanent proof protocol remains compatible with v1.0.2. Actual length is enforced in the normal browser and declared length on activation backend; a derived proof cannot attest a malicious client's source-PIN length. See SECURITY_REVIEW for this preserved protocol boundary.
- Before rollback to old auth code, all pending accounts must be suspended. This is a critical manual prerequisite, not an optional cleanup. No helper/installer/rollback was run against production.
- _STATE preview/ticket/receipt rows and audit/WAL histories grow; no unsafe physical pruning is introduced. Whole-master read and global-lock throughput constraints remain. Large2000-pupil synthetic success is not cloud latency or quota evidence. Inspect live metrics before school-wide use.
- v1.0.2 sessionStorage draft durability, cross-tab unsent intentions, Docs pagination/Drive side effects and actual PDF correctness still need the prior release's live acceptance checks. This release does not claim to remove those constraints. Historical reports are in docs/v1.0.2.
