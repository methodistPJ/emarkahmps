# Security review — v1.0.3 RC1

Scope: targeted source review plus local synthetic tests. No live penetration test, deployment/access inspection or production credential was used. This is a release candidate pending Google staging acceptance.

## Trust boundaries and controls

- Existing session/RBAC, HMAC pepper, PBKDF2-SHA256600000, receipt replay, record versions, read consistency lock and WAL remain. No table/header or permanent-account verifier migration.
- Import/preview/details/readiness/prepare/issuance are admin-only. Workbook fields are allowlisted; infrastructure/secrets, arbitrary tables/row coordinates, ADMINISTRATOR role and PIN columns are not accepted. Source/workbook/schema/parser contract equality is tested.
- Pending teachers store only peppered derived verifier plus must_change metadata. login_ refuses to issue ordinary sessions, and session_ independently refuses all pending accounts even if a pre-existing session record is forged/stale. Temporary seven-character handling is confined to temporaryProof; M.proof for ordinary PIN remains10–64.
- Common temporary PIN alone cannot claim an account. Administrator verifies identity and issues an individual144-bit code with48-hour expiry. Hash is HMAC-bound to user ID. Only digest, expiry and generation persist. Raw code is returned once after a committed issuance; compact replay receipt contains no code. Lost-code response requires fresh issuance, revoking earlier codes/tickets by auth_version/generation.
- activationBegin requires correct identity/alias, temporary derived proof and private code. It issues a256-bit restricted ticket stored only by hash with10-minute expiry and account version/generation. It is not a normal session token. activationFinish checks that binding under the same exclusive transaction lock; first successful change removes temporary/activation state, consumes the ticket and bumps auth_version. Parallel/duplicate attempts cannot establish a second permanent credential.
- Failed activation attempts are audited without secrets. Five identity failures trigger15-minute cooldown; activation traffic also has a global60-per-minute limit. Authenticated issuance is bounded1–30 accounts and auditable. Issuance and permanent activation are blocked during active year archiving.
- Excel parsing uses locally vendored JSZip3.10.1 and DOMParser, no CDN/parser service. ZIP preflight rejects encryption, ZIP64/multipart, traversal/duplicates, unsupported methods, excessive counts and advertised sizes. Streaming decompression enforces actual byte limits and CRC before XML parsing; declared-size lies are rejected. XML DOCTYPE/entities, external relationships, macro/externalLink/embedded parts and input formulas/errors are rejected. Cell/header/reference types and mandatory sheets are validated again by backend.
- Class/student/teacher references are deterministic; missing rows are not deletions. Preview is actor/content/database-bound with15-minute expiry; commit revalidates all relationships. Existing PINs are never replaced by import. Database primary-key corruption and ambiguous enrolment/history changes fail closed. Text identifiers are formatted before writes and year copies; no inferred zero-padding.
- School profile commits in _STATE; only SCHOOL_NAME/HEADMISTRESS_NAME are derived to Script Properties after WAL commit or on next locked request. ACADEMIC_YEAR and all infrastructure secrets/IDs are not writable from workbook.
- All new helpers are private underscore functions behind rpc. Client rendering escapes imported strings; backend/formula-safe writes remain. No plaintext activation code/ticket/permanent PIN/proof is written to audit/diagnostic logs. WAL legitimately contains actual school records and credential digests, so Sheets/project/backup access must remain restricted.

## Protocol and residual boundaries

The preserved verifier protocol accepts a derived proof, not plaintext PIN. Browser enforces actual10–64 length; activationFinish also validates declared pin_length and rejects reusing the temporary digest. As with the existing userSave proof protocol, the server cannot cryptographically attest a malicious client's claimed source-PIN length from a derived proof alone. A stronger server-attested password policy would require a separately designed authentication protocol change; this release does not pretend otherwise or log/transmit permanent plaintext PINs. Trusted administrators can already provision account verifiers in v1.0.2.

Public challenge salts/proofs are compatible with existing accounts; proof is a reusable credential, not a one-time challenge nonce. Preserve HTTPS and pepper secrecy. Activation codes/tickets exist transiently in authorized browser memory/DOM; a compromised administrator browser/XSS/approved recipient can leak them. Rate limiting and expiry do not replace private distribution. Do not record screenshots of actual issued codes.

sessionStorage/drafts retain v1.0.2 limits: no encryption/durable tab-close guarantee, no cross-device draft merging. The new wizard keeps workbook and temporary proof list in memory only and clears them after commit; refresh requires validating the workbook again. The existing RPC mutation ledger is memory-only except mark/remark drafts. New setup receipts and deterministic matching cover import retries, but unrelated legacy Drive/Docs side effects retain their known external-transaction limits.

Workbook protection prevents accidental edits, not malicious input. Server validation remains authoritative if a client bypasses the parser. XLSX/HTMLService/Sheets/trigger quotas and real Safari behaviour remain staging tests. Preview/expired ticket rows are not physically pruned; _STATE growth needs operational monitoring, not unsafe deletion of recovery state.

## Critical rollback constraint

v1.0.2 does not understand must_change. Never roll back while active pending accounts retain the common temporary verifier. Run/review the private suspension safeguard while v1.0.3 is still installed, verify pending users are inactive with bumped versions, then revert code/HEAD as in ROLLBACK_GUIDE. This is manual guidance, not an action executed by this engagement.
